这份 notebook 从第 2 章的后半部分开始，重点是把一段文本变成语言模型可以接收的输入。完整流程可以压缩成一条链：

```text
原始文本
  → GPT-2 分词器
  → token IDs
  → 滑动窗口产生输入与目标
  → DataLoader 组成批次
  → token embedding + position embedding
  → LLM 的输入向量
```

本文只准备数据，还没有训练语言模型。

## 1. 下载示例文本

本章使用 Edith Wharton 的短篇小说 _The Verdict_ 作为练习文本。

```python
import os
import urllib.request

if not os.path.exists("the-verdict.txt"):
    url = ("https://raw.githubusercontent.com/rasbt/"

           "the-verdict.txt")
    file_path = "the-verdict.txt"
    urllib.request.urlretrieve(url, file_path)
```

逐行来看：

- `import os` 导入 Python 的操作系统工具。这里用它检查文件是否已经存在。
- `import urllib.request` 导入网络请求工具，用于从网址下载文件。
- `os.path.exists("the-verdict.txt")` 返回一个布尔值：文件存在时是 `True`，不存在时是 `False`。
- `not` 把结果反转。因此，只有文件不存在时，`if` 里面的下载代码才会运行。
- 圆括号中的三个字符串会被 Python 自动拼接成一个完整 URL。拆成多行只是为了便于阅读。
- `file_path` 是下载后保存到本地的文件名。
- `urlretrieve(url, file_path)` 从 `url` 下载内容，并写入 `file_path`。

原 notebook 的这个单元格有缩进丢失。上面按照作者官方 Chapter 2 notebook 恢复了缩进；这不是改变算法，而是确保 `url`、`file_path` 和下载动作都只在文件不存在时执行。如果下载语句放在 `if` 外面，那么文件已经存在时，变量 `url` 可能没有被创建，代码会报 `NameError`。

## 2. 创建 GPT-2 分词器

```python
import tiktoken
```

`tiktoken` 是 OpenAI 开源的快速分词库。语言模型不能直接对字符串做矩阵运算，因此第一步是把文本拆成 token，再把每个 token 映射为整数 ID。

```python
tiktoken.__version__
```

输出：

```text
'0.13.0'
```

`__version__` 保存当前安装的版本号。在 Jupyter notebook 中，把一个值放在单元格最后一行，会自动显示它；如果在普通 `.py` 文件中运行，则通常要写成 `print(tiktoken.__version__)`。

```python
tokenizer = tiktoken.get_encoding("gpt2")
```

- `get_encoding("gpt2")` 加载 GPT-2 使用的 Byte Pair Encoding（BPE）分词规则与词表。
- `tokenizer` 不是模型。它不预测文本，只负责在文本和 token IDs 之间转换。
- token ID 只是词表中的索引。例如，较大的 ID 不表示这个 token “更重要”。

## 3. 把文本编码成 token IDs

```python
with open("the-verdict.txt", "r", encoding="utf-8") as f:
    raw_text = f.read()

encoded_text = tokenizer.encode(raw_text)
print(len(encoded_text))
```

输出：

```text
5145
```

这里发生了三次形式转换：

1. `open(..., "r", encoding="utf-8")` 以只读模式打开 UTF-8 文本。
2. `f.read()` 读取整个文件，得到一个 Python 字符串，并保存为 `raw_text`。
3. `tokenizer.encode(raw_text)` 把字符串转换成一个整数列表，并保存为 `encoded_text`。

`with` 会在代码块结束时自动关闭文件，即使读取时发生异常，也不需要手动调用 `f.close()`。最后的 `len(encoded_text)` 统计的是 **token 数量**，不是字符数，也不是单词数。BPE token 可能是完整单词、单词的一部分、标点，甚至包含前导空格。

## 4. 理解“下一个 token”训练目标

```python
enc_sample = encoded_text[50:]
context_size = 4
x = enc_sample[:context_size]
y = enc_sample[1:context_size + 1]

print(f"x: {x}")
print(f"y:      {y}")
```

输出：

```text
x: [290, 4920, 2241, 287]
y:      [4920, 2241, 287, 257]
```

- `encoded_text[50:]` 跳过前 50 个 token，只是为了选取一个便于演示的片段。
- `context_size = 4` 表示一次给模型看 4 个 token。
- `x` 取得位置 `0` 到 `3` 的 4 个 token。
- `y` 从位置 `1` 开始，也取得 4 个 token。

如果片段写成抽象符号，关系会非常清楚：

| 位置  | 0     | 1     | 2     | 3     | 4     |
| ----- | ----- | ----- | ----- | ----- | ----- |
| token | $t_0$ | $t_1$ | $t_2$ | $t_3$ | $t_4$ |
| `x`   | $t_0$ | $t_1$ | $t_2$ | $t_3$ |       |
| `y`   |       | $t_1$ | $t_2$ | $t_3$ | $t_4$ |

因此，`y` 就是 `x` 向右移动一个位置后的结果。模型将学习：看到 `x` 的每个位置及其左侧上下文时，对应的下一个 token 应该是 `y` 中同一列的值。

### 把 ID 解码成人能读懂的文本

```python
for i in range(1, context_size + 1):
    context = enc_sample[:i]
    desired = enc_sample[i]
    print(tokenizer.decode(context), "->", tokenizer.decode([desired]))
```

输出：

```text
 and ->  established
 and established ->  himself
 and established himself ->  in
 and established himself in ->  a
```

- `range(1, context_size + 1)` 生成 `1, 2, 3, 4`。结尾值不包含在 `range` 中，所以需要写 `+ 1`。
- `enc_sample[:i]` 让上下文从 1 个 token 逐步增长到 4 个 token。
- `enc_sample[i]` 选择紧跟在当前上下文之后的那个 token。
- `decode(context)` 把多个 token IDs 转回字符串。
- `decode([desired])` 接收一个 ID 列表，因此单个整数 `desired` 也要放进方括号。

输出表达的是：给定左边不断增长的上下文，模型希望预测箭头右边的 token。

### 直接查看同一关系的数字形式

```python
for i in range(1, context_size + 1):
    context = enc_sample[:i]
    desired = enc_sample[i]
    print(f" {context} -> {desired}")
```

输出：

```text
 [290] -> 4920
 [290, 4920] -> 2241
 [290, 4920, 2241] -> 287
 [290, 4920, 2241, 287] -> 257
```

这段循环没有改变数据，只是不再解码。它帮助我们把“可读文本”和“模型实际接收的整数”联系起来。

## 5. 用 PyTorch Dataset 创建滑动窗口

```python
import torch
```

PyTorch 负责张量、数据批次和后续的神经网络计算。

```python
torch.__version__
```

输出：

```text
'2.13.0+cpu'
```

和 `tiktoken.__version__` 一样，这用于记录实验环境。版本信息在排查不同电脑上的行为差异时很有用。

```python
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
    def __init__(self, text, tokenizer, max_length, stride):
        self.input_ids = []
        self.target_ids = []

        token_ids = tokenizer.encode(text, allowed_special={"<|endoftext|>"})

        for i in range(0, len(token_ids) - max_length, stride):
            input_seq = token_ids[i:i + max_length]
            target_seq = token_ids[i + 1:i + max_length + 1]

            self.input_ids.append(torch.tensor(input_seq, dtype=torch.long))
            self.target_ids.append(torch.tensor(target_seq, dtype=torch.long))

    def __len__(self):
        return len(self.input_ids)

    def __getitem__(self, idx):
        return self.input_ids[idx], self.target_ids[idx]
```

### 类和初始化方法

- `class GPTDatasetV1(Dataset)` 创建一个继承自 PyTorch `Dataset` 的自定义数据集。继承后，PyTorch 的 `DataLoader` 就知道如何向它索取样本。
- `__init__` 在创建数据集对象时运行。
- `text` 是完整字符串；`tokenizer` 负责编码；`max_length` 是每个样本的 token 数；`stride` 是窗口每次前进的距离。
- `self.input_ids` 与 `self.target_ids` 是两个列表，用来保存所有输入序列和目标序列。

### 一次编码完整文本

```python
token_ids = tokenizer.encode(text, allowed_special={"<|endoftext|>"})
```

完整文本只编码一次。`allowed_special` 表示如果文本中真的出现 `<|endoftext|>`，允许分词器把它当作 GPT-2 的特殊 token，而不是抛出错误。它不会自动把这个 token 添加到文本里。

### 移动窗口

```python
for i in range(0, len(token_ids) - max_length, stride):
```

- 起点是 `0`。
- 终点保证输入窗口之后至少还有一个 token，因为目标需要向右移动一位。
- 每次增加 `stride`，控制相邻样本重叠多少。

例如，`max_length=4`、`stride=2` 时，窗口起点是 `0, 2, 4, ...`，相邻输入会重叠两个 token。`stride=4` 时，输入窗口之间不重叠。

```python
input_seq = token_ids[i:i + max_length]
target_seq = token_ids[i + 1:i + max_length + 1]
```

这两行把前面的小例子推广到整篇文本：输入从 `i` 开始，目标从 `i + 1` 开始，但二者长度相同。

```python
self.input_ids.append(torch.tensor(input_seq, dtype=torch.long))
self.target_ids.append(torch.tensor(target_seq, dtype=torch.long))
```

- `torch.tensor(...)` 把 Python 整数列表转换为 PyTorch 张量。
- `dtype=torch.long` 使用 64 位整数。PyTorch 的 embedding 层需要整数索引，不能使用普通浮点数作为 token ID。
- `append` 把当前窗口保存进数据集。

### 让 DataLoader 能读取数据集

- `__len__` 返回样本总数，所以 `len(dataset)` 可以工作。
- `__getitem__(idx)` 返回第 `idx` 个 `(input, target)` 对，所以 `dataset[0]` 可以工作。
- Python 中以双下划线包围的方法叫特殊方法。`DataLoader` 会在后台调用它们。

## 6. 把样本组成批次

```python
def create_dataloader_v1(text, batch_size=2, max_length=256,
                         stride=128, shuffle=True, drop_last=True,
                         num_workers=0):
    tokenizer = tiktoken.get_encoding("gpt2")
    dataset = GPTDatasetV1(text, tokenizer, max_length, stride)
    dataloader = DataLoader(dataset,
                            batch_size=batch_size,
                            shuffle=shuffle,
                            drop_last=drop_last,
                            num_workers=num_workers)
    return dataloader
```

这个函数把创建分词器、数据集和 DataLoader 的步骤包装在一起：

- `batch_size`：一次返回多少个样本。
- `max_length`：每个样本包含多少个 token，也叫上下文长度。
- `stride`：滑动窗口每次前进多少个 token。
- `shuffle`：每轮是否打乱样本顺序。训练时通常开启；观察固定示例时关闭。
- `drop_last`：最后一个批次不足 `batch_size` 时是否丢弃。固定形状的训练批次通常更方便。
- `num_workers=0`：由当前 Python 进程加载数据。这个设置最简单，也更适合 notebook 和 Windows 环境。
- `return dataloader`：把创建好的加载器交给调用者。

## 7. 取出一个批次

```python
with open("the-verdict.txt", "r", encoding="utf-8") as f:
    raw_text = f.read()
```

这里重新读取文本，是为了让这个实验部分可以独立运行。

```python
dataloader = create_dataloader_v1(
    raw_text,
    batch_size=8,
    max_length=4,
    stride=4,
    shuffle=False,
    drop_last=True,
    num_workers=0
)
data_iter = iter(dataloader)
input, target = next(data_iter)
print(f"Input:\n", input)
print(f"Target:\n", target)
```

输出：

```text
Input:
 tensor([[   40,   367,  2885,  1464],
        [ 1807,  3619,   402,   271],
        [10899,  2138,   257,  7026],
        [15632,   438,  2016,   257],
        [  922,  5891,  1576,   438],
        [  568,   340,   373,   645],
        [ 1049,  5975,   284,   502],
        [  284,  3285,   326,    11]])
Target:
 tensor([[  367,  2885,  1464,  1807],
        [ 3619,   402,   271, 10899],
        [ 2138,   257,  7026, 15632],
        [  438,  2016,   257,   922],
        [ 5891,  1576,   438,   568],
        [  340,   373,   645,  1049],
        [ 5975,   284,   502,   284],
        [ 3285,   326,    11,   287]])
```

- `batch_size=8` 让一个批次含有 8 个序列。
- `max_length=4` 让每个序列含有 4 个 token。
- `stride=4` 让相邻输入窗口不重叠。
- `shuffle=False` 保留原文顺序，便于检查。
- `iter(dataloader)` 创建一个迭代器。
- `next(data_iter)` 取出第一个批次，并拆成输入与目标。

因此，`input` 和 `target` 的形状都是 `[8, 4]`：第一维是批次大小，第二维是序列长度。这里的变量名 `input` 会遮蔽 Python 内置的 `input()` 函数；不影响本例，但在自己的项目中用 `inputs` 会更清楚。

每一行目标仍然是对应输入向左错开一个 token 后的结果。例如：

```text
input:  [t0, t1, t2, t3]
target: [t1, t2, t3, t4]
```

## 8. 把 token IDs 映射为向量

```python
dir(tokenizer)
```

`dir` 会列出对象可访问的属性和方法。这是一种探索 Python 对象的方式，但输出很长。这里真正要用的是下面的 `n_vocab`。

```python
torch.manual_seed(123)
vocab_size = tokenizer.n_vocab
output_dim = 256
embedding_layer = torch.nn.Embedding(
    num_embeddings=vocab_size,
    embedding_dim=output_dim
)
```

- `torch.manual_seed(123)` 固定 PyTorch 随机数种子，使随机初始化在重复运行时更容易复现。
- `tokenizer.n_vocab` 是 GPT-2 词表大小，即 embedding 表需要多少行。
- `output_dim=256` 表示每个 token 用 256 个浮点数表示。
- `torch.nn.Embedding` 创建一个可训练的查找表，形状为 `[vocab_size, output_dim]`。

```python
print(embedding_layer.weight.shape)
```

输出：

```text
torch.Size([50257, 256])
```

`weight` 是 embedding 层的参数矩阵。输入一个 token ID，就相当于取出矩阵中对应的那一行。刚创建时这些值是随机的；只有经过训练后，它们才会形成对模型有用的表示。

```python
token_embeddings = embedding_layer(input)
token_embeddings.shape
```

输出：

```text
torch.Size([8, 4, 256])
```

输入 token IDs 的形状是 `[8, 4]`。每个 ID 被替换为一个 256 维向量后，形状变成 `[8, 4, 256]`：

| 维度    | 含义                  | 当前值 |
| ------- | --------------------- | ------ |
| 第 1 维 | 一个批次中的序列数    | 8      |
| 第 2 维 | 每个序列的 token 数   | 4      |
| 第 3 维 | 每个 token 的向量维度 | 256    |

## 9. 添加位置信息

token embedding 只由 token ID 决定。同一个 token 无论出现在第一位还是第四位，查到的向量都相同。因此还需要告诉模型每个 token 在序列中的位置。

```python
context_length = 4
pos_embedding_layer = torch.nn.Embedding(
    num_embeddings=context_length,
    embedding_dim=output_dim
)
pos_embeddings = pos_embedding_layer(torch.arange(context_length))
```

- `context_length=4` 对应当前序列长度。
- 位置 embedding 表有 4 行，分别代表位置 `0, 1, 2, 3`。
- 每个位置向量同样有 256 维，所以可以与 token embedding 相加。
- `torch.arange(context_length)` 生成整数张量 `[0, 1, 2, 3]`。
- 把这些位置索引传入 embedding 层，得到 4 个位置向量。

```python
pos_embeddings.shape
```

输出：

```text
torch.Size([4, 256])
```

结果是 `[4, 256]`：4 个位置，每个位置一个 256 维向量。

```python
input_embeddings = token_embeddings + pos_embeddings
input_embeddings.shape
```

输出：

```text
torch.Size([8, 4, 256])
```

这里两个张量的形状看起来不同：

```text
token_embeddings: [8, 4, 256]
pos_embeddings:       [4, 256]
```

PyTorch 使用 **broadcasting（广播）**，把同一组 `[4, 256]` 位置向量应用到批次中的 8 个序列。因此结果仍是 `[8, 4, 256]`。

相加后的每个向量同时携带两类信息：

- token embedding 表示“这是什么 token”；
- position embedding 表示“它位于序列的哪里”。

这个 `input_embeddings` 就是后续 Transformer 模块接收的输入。

## 10. 最终理解

这一段代码最重要的不是记住 API，而是理解形状和数据的变化：

| 阶段                | 数据示例                | 形状              |
| ------------------- | ----------------------- | ----------------- |
| 原始文本            | Python 字符串           | 无固定张量形状    |
| token IDs           | 每个 token 对应一个整数 | `[全部 token 数]` |
| 一个输入批次        | 8 个长度为 4 的序列     | `[8, 4]`          |
| token embeddings    | 每个 ID 变成 256 维向量 | `[8, 4, 256]`     |
| position embeddings | 4 个位置各有一个向量    | `[4, 256]`        |
| 最终输入 embeddings | token 与位置向量相加    | `[8, 4, 256]`     |

我现在对这段流程的理解是：语言模型的训练目标来自文本本身。我们不需要人工为每个词标标签，只要把原序列复制一份并向右移动一个 token，就得到了每个位置的正确答案。Embedding 层再把离散 ID 转成可以参与神经网络计算的连续向量。

下一步将是把这些输入向量送入注意力机制，学习序列中不同位置之间的关系。
