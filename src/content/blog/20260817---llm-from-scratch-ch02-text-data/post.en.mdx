The book uses the construction of a GPT-2-style LLM as its main thread, gradually introducing the major components involved in building and training an LLM.
This study note mainly corresponds to the latter part of Chapter 2. Its focus is turning a piece of text into input that a language model can process. The full pipeline can be condensed into one chain:

```text
raw text
  → GPT-2 tokenizer
  → token IDs
  → sliding-window inputs and targets
  → DataLoader batches
  → token embeddings + positional embeddings
  → input vectors for the LLM
```

This article only prepares the data; it does not train a language model. My current goal is to form an initial understanding of this pipeline while building up my coding knowledge. I will leave different tokenizers and more advanced encoding methods for deeper study later.

## 5. Creating sliding windows with a PyTorch Dataset

```python
import torch
torch.__version__
```

Output:

```text
'2.13.0+cpu'
```

Recording version information is useful when diagnosing differences between computers.

```python
from torch.utils.data import Dataset, DataLoader

class GPTDatasetV1(Dataset):
    def __init__(self, text, tokenizer, max_length, stride):
        self.input_ids = []
        self.target_ids = []

        token_ids = tokenizer.encode(text, allowed_special={"<|endoftext|>"})

        for i in range(0, len(token_ids) - max_length, stride):
            input_seq = token_ids[i:i + max_length]
            target_seq = token_ids[i + 1:i + max_length + 1]

            self.input_ids.append(torch.tensor(input_seq, dtype=torch.long))
            self.target_ids.append(torch.tensor(target_seq, dtype=torch.long))

    def __len__(self):
        return len(self.input_ids)

    def __getitem__(self, idx):
        return self.input_ids[idx], self.target_ids[idx]
```

- `GPTDatasetV1(Dataset)` defines a class that inherits from PyTorch’s `Dataset`. Through this inheritance, PyTorch’s `DataLoader` knows how to request samples from it.
  This illustrates how classes are often used to package related functionality that needs to preserve state and be reused.

### Tokenizing and encoding the entire text

```python
token_ids = tokenizer.encode(text, allowed_special={"<|endoftext|>"})
```

`allowed_special` means that if the literal text `<|endoftext|>` appears, the tokenizer may treat it as GPT-2’s special token instead of raising an error. It does not automatically add this token to the text.

### Moving the window

```python
for i in range(0, len(token_ids) - max_length, stride):
    input_seq = token_ids[i:i + max_length]
    target_seq = token_ids[i + 1:i + max_length + 1]
```

- The first window starts at `0`.
- The endpoint ensures that at least one token remains after the input window because the target must be shifted one position to the right.
- Each iteration advances by `stride`, controlling how much neighboring samples overlap.

For example, with `max_length=4` and `stride=2`, window starting positions are `0, 2, 4, ...`, so neighboring inputs overlap by two tokens. With `stride=4`, input windows do not overlap.

Suppose part of `token_ids` is `[2, 5, 420, 8, 9, 13, 20, 67, 99]`. The first sample is always:

```text
input_seq:  [2, 5, 420, 8]
target_seq: [5, 420, 8, 9]
```

`stride` determines where the next window starts, not how the current `target_seq` is shifted. With `stride=2`, the next sample is:

```text
input_seq:  [420, 8, 9, 13]
target_seq: [8, 9, 13, 20]
```

With `stride=4`, the next sample is:

```text
input_seq:  [9, 13, 20, 67]
target_seq: [13, 20, 67, 99]
```

```python
self.input_ids.append(torch.tensor(input_seq, dtype=torch.long))
self.target_ids.append(torch.tensor(target_seq, dtype=torch.long))
```

- A PyTorch embedding layer requires an integer token-ID tensor, such as `torch.long`, and cannot use floating-point values as indices.

## 6. Generating batches with DataLoader

```python
def create_dataloader_v1(text, batch_size=2, max_length=256,
                         stride=128, shuffle=True, drop_last=True,
                         num_workers=0):
    tokenizer = tiktoken.get_encoding("gpt2")
    dataset = GPTDatasetV1(text, tokenizer, max_length, stride)
    dataloader = DataLoader(dataset,
                            batch_size=batch_size,
                            shuffle=shuffle,
                            drop_last=drop_last,
                            num_workers=num_workers)
    return dataloader
```

This function packages tokenizer, dataset, and DataLoader creation together:

- `batch_size`: the number of samples in each batch.
- `max_length`: the number of tokens in each sample, also called the context length.
- `stride`: the number of tokens by which the sliding window advances.
- `shuffle`: whether to randomize sample order each epoch. This is usually enabled during training and disabled during validation or testing.
- `drop_last`: whether to discard the final batch when it contains fewer than `batch_size` samples.
- `num_workers`: the number of additional subprocesses used to prepare batches in parallel. With `0`, the current Python process loads the data.

## 8. Mapping token IDs to vectors

```python
torch.manual_seed(123)
vocab_size = tokenizer.n_vocab
output_dim = 256
embedding_layer = torch.nn.Embedding(
    num_embeddings=vocab_size,
    embedding_dim=output_dim
)
```

- `torch.manual_seed(123)` fixes PyTorch’s random seed, making random initialization easier to reproduce. This is needed here because `nn.Embedding` initializes its weight table randomly.
- `tokenizer.n_vocab` is the size of the GPT-2 vocabulary, determining how many rows the embedding table needs.
- `output_dim=256` means that each token is represented by 256 floating-point values.
- `torch.nn.Embedding` creates a trainable lookup table with shape `[vocab_size, output_dim]`.

```python
print(embedding_layer.weight.shape)
```

Output:

```text
torch.Size([50257, 256])
```

This means that each of the 50,257 token IDs in the vocabulary maps to its own 256-dimensional vector.

```python
token_embeddings = embedding_layer(input)
token_embeddings.shape
```

Output:

```text
torch.Size([8, 4, 256])
```

| Dimension | Meaning                           | Current value |
| --------- | --------------------------------- | ------------- |
| First     | Number of sequences in one batch  | 8             |
| Second    | Number of tokens in each sequence | 4             |
| Third     | Embedding dimension of each token | 256           |

## 9. Adding position information

A token embedding depends only on the token ID. The same token retrieves the same vector whether it appears in the first or fourth position. The model therefore also needs information about each token’s position in the sequence.

```python
context_length = 4
pos_embedding_layer = torch.nn.Embedding(
    num_embeddings=context_length,
    embedding_dim=output_dim
)
pos_embeddings = pos_embedding_layer(torch.arange(context_length))
```

- `torch.arange(context_length)` creates the integer tensor `[0, 1, 2, 3]`.
- Passing these indices into the positional embedding layer retrieves the corresponding vectors, thereby encoding position information.

```python
pos_embeddings.shape
```

Output:

```text
torch.Size([4, 256])
```

The result is `[4, 256]`: four positions, each represented by a 256-dimensional vector.

```python
input_embeddings = token_embeddings + pos_embeddings
input_embeddings.shape
```

Output:

```text
torch.Size([8, 4, 256])
```

The two tensors initially appear to have different shapes:

```text
token_embeddings: [8, 4, 256]
pos_embeddings:       [4, 256]
```

PyTorch uses **broadcasting** to apply the same `[4, 256]` positional vectors to all eight sequences in the batch. The result therefore remains `[8, 4, 256]`.

Each resulting vector now carries two kinds of information:

- The token embedding represents “what token is this?”
- The positional embedding represents “where is it in the sequence?”

This `input_embeddings` tensor is the input received by the later Transformer blocks.

## 10. Summary

The most important lesson is not memorizing APIs, but understanding how data gradually becomes vectors that the model can process:

```text
Raw text (Python string)
│
│  GPT-2 BPE tokenizer splits the text
▼
Tokens (words, subwords, or punctuation pieces)
│
│  GPT-2 vocabulary maps each token to an integer
▼
Token IDs
│
│  Sliding window and DataLoader
▼
Input ID batch [batch_size, seq_len]
│
│  Token embedding lookup
▼
Token embeddings [batch_size, seq_len, embed_dim]

Position IDs [0, 1, ..., seq_len-1]
│
│  Positional embedding lookup
▼
Positional embeddings [seq_len, embed_dim]

Token embeddings [batch_size, seq_len, embed_dim]
+ positional embeddings [seq_len, embed_dim] (broadcast across the batch dimension)
│
│  Element-wise addition
▼
Final input embeddings [batch_size, seq_len, embed_dim]
│
▼
Later Transformer blocks
```

The diagram separates token splitting from token-ID mapping to make the concepts clearer. In the code, the `tiktoken` library performs both steps through `tokenizer.encode(raw_text)`. The training targets are produced from a copy of the same token IDs shifted one position to the right.

The next step is to pass these input vectors into an attention mechanism so the model can learn relationships between different positions in a sequence.
