## 为什么从网站开始

我计划通过一系列学习项目了解 AI 和 Agent。项目 0 不是 AI 项目，而是先搭建一个网站，用它记录后面的学习过程。

开始时，我几乎没有编程和工程经验。因此，这个网站本身也是学习的一部分。

## 到目前为止完成的事情

- 安装并使用 Bun 运行项目
- 了解 Astro 项目的基本目录结构
- 修改网站名称、作者、简介和 GitHub 链接
- 建立中文优先的双语结构
- 简化首页、About、Blog 和 Notes 页面
- 移除模板自带的示例文章、图片和目前不需要的功能
- 关闭评论、统计和数据库相关功能
- 检查字体、图标和第三方资源的许可证
- 使用 Git 记录并推送每个阶段的修改
- 使用 Vercel 部署网站并检查正式构建结果
- 配置正确的网站地址、canonical URL、sitemap 和 RSS

## 我目前学到的东西

### 配置和内容不同

网站配置决定标题、语言和菜单等整体行为；Markdown 和 MDX 文件则保存具体文章。

### 检查比猜测更可靠

遇到错误时，错误信息、文件搜索和 Git diff 通常可以帮助确定问题发生在哪里。

### 小步修改更容易排错

每完成一组相关修改，就进行检查和提交。这样出现问题时，更容易知道是哪次修改造成的。

### 本地成功不代表部署一定成功

本地检查和构建都通过后，第一次 Vercel 部署仍然因为 Node.js 版本不兼容而失败。通过阅读部署日志，我发现旧版适配器无法识别 Node.js 24，并错误回退到了已经不受支持的 Node.js 18。

最后，我在 `package.json` 中明确指定使用 Node.js 22。这个过程让我第一次看到本地环境和部署环境可能存在差异，也体会到部署日志的重要性。

## 下一步

网站现在已经完成第一次部署。下一步，我会通过 Git 分支和 Vercel Preview 测试这篇文章，继续修改首页和 About 页面，并学习一篇文章从草稿、预览到正式发布的完整流程。
