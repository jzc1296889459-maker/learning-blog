## 1. 导入模型与第 2 章工具

- `torch` 提供 tensor、checkpoint loading、device 和可选的 model compilation。
- Qwen3 相关导入提供 downloader、tokenizer、model architecture 和 0.6B configuration。
- `get_device` 直接复用第 2 章的实现，避免重复编写 device detection。

下面第一行 import 存在于 Notebook 中，但后面的 loader 没有使用它：

```python
from threading import local


def load_model_and_tokenizer(
        which_model, device, use_compile, local_dir="qwen3"
):
    if which_model == "base":
        download_qwen3_small(
            kind="base", tokenizer_only=False, out_dir=local_dir
        )

        tokenizer_path = Path(local_dir) / "tokenizer-base.json"
        model_path = Path(local_dir) / "qwen3-0.6B-base.pth"
        tokenizer = Qwen3Tokenizer(tokenizer_file_path=tokenizer_path)
    elif which_model == "reasoning":
        download_qwen3_small(
                    kind="reasoning", tokenizer_only=False, out_dir=local_dir
                )

        tokenizer_path = Path(local_dir) / "tokenizer-reasoning.json"
        model_path = Path(local_dir) / "qwen3-0.6B-reasoning.pth"
        tokenizer = Qwen3Tokenizer(
            tokenizer_file_path=tokenizer_path,
            apply_chat_template=True,
            add_generation_prompt=True,
            add_thinking=True,
            )
    else:
        raise ValueError(f"Invalid choice: which_model={which_model}")
    model = Qwen3Model(QWEN_CONFIG_06_B)
    model.load_state_dict(torch.load(model_path))

    model.to(device)

    if use_compile:
        torch._dynamo.config.allow_unspec_int_on_nn_module = True
        model = torch.compile(model)

    return model, tokenizer

```

这个 loader 支持两种模型：

1. `base` branch 下载 base weights，设置 base tokenizer 和 checkpoint 路径，并创建不使用 chat
   template 的 tokenizer。
2. `reasoning` branch 下载经过 reasoning tuning 的文件。它的 tokenizer 会应用 chat template、
   添加 assistant generation prompt，并启用 thinking tokens。
3. 任何其他值都会立刻触发 `ValueError`，而不是静默加载错误模型。
4. 确定路径后，`Qwen3Model(QWEN_CONFIG_06_B)` 创建两种权重共用的 0.6B architecture。
5. `torch.load` 读取 checkpoint，`load_state_dict` 把权重装入对应层。
6. `model.to(device)` 让模型参数与后面的 input tensor 位于同一 device。
7. 如果 `use_compile` 为 true，代码先启用 Dynamo 的 unspecialized integer support，再用
   `torch.compile` 包装模型。
8. 函数最终返回相互匹配的 model 和 tokenizer。

## 2. 生成一道数学题的答案

```python
from reasoning_from_scratch.ch02 import(
    generate_text_basic_stream_cache
)

prompt = (
    r"If $a+b=3$ and $ab=\tfrac{13}{6}$, "
    r"what is the value of $a^2+b^2$?"
)

input_token_ids_tensor = torch.tensor(
    tokenizer.encode(prompt),
    device=device
).unsqueeze(0) # add a batch dimension

all_token_ids = []

for token in generate_text_basic_stream_cache(
    model=model,
    token_ids=input_token_ids_tensor,
    max_new_tokens=2048,
    eos_token_id=tokenizer.eos_token_id
):
    token_id = token.squeeze(0) # remove the batch dimension
    decoded_id = tokenizer.decode(token_id.tolist())
    print(
        decoded_id,
        end="",
        flush=True
    )
    all_token_ids.append(token_id)

all_tokens = tokenizer.decode(all_token_ids)
```

Prompt 要求根据 $a+b=3$ 和 $ab=13/6$ 求 $a^2+b^2$。利用 $(a+b)^2-2ab$，可以得到
$14/3$。

代码按以下顺序运行：

- `generate_text_basic_stream_cache` 复用第 2 章带 KV cache 的 generator。
- raw string 保留 `\tfrac` 这样的 LaTeX backslash。
- `tokenizer.encode(prompt)` 返回一维 Python token ID list。
- `torch.tensor(..., device=device)` 直接在模型所在 device 创建 input。
- `.unsqueeze(0)` 添加 batch dimension，把 `(sequence_length,)` 变成
  `(1, sequence_length)`。
- 每个 streamed token 也带 batch dimension，`squeeze(0)` 将它删除。
- `.tolist()` 把 token tensor 转成 `tokenizer.decode` 接受的形式。
- `end=""` 和 `flush=True` 把 token fragment 连续、即时地显示出来。
- 同一份 token tensor 也会存入 `all_token_ids`，供最后重建完整 response。

模型回答最终以 `\boxed{\dfrac{14}{3}}` 结束，数学结果正确。

### Encode/decode shape pattern

Notebook 用下面的例子概括 Python list 与 batched model tensor 之间的边界：

```python
ids = tokenizer.encode("Hello")                 # list[int], length L
x = torch.tensor(ids).unsqueeze(0)                # shape: (1, L)
generated = generate_text_basic_cache(model, x, 5)  # shape: (1, T)
text = tokenizer.decode(generated[0].tolist())    # list[int] -> str
```

`generate_text_basic_cache` 返回完整的 `(batch_size, generated_length)` tensor。直接迭代这个
tensor 时，迭代的是 batch dimension，并不是一个个 token。需要逐 token 处理时，应使用
`generate_text_basic_stream_cache`。

原始 response 使用 `\(...\)` 和 `\[...\]` LaTeX delimiter。下面只为 Notebook display 把它们转换
成 Markdown renderer 能识别的 delimiter：

```python
from IPython.display import Markdown, display

    all_tokens
    .replace(r"\(", "$")
    .replace(r"\)", "$")
    .replace(r"\[", "$$")
    .replace(r"\]", "$$")

display(Markdown(rendered))
```

## 3. 封装 streamed generation

Benchmark evaluation 需要得到完整字符串，同时也可以选择保留 live output。下面的 wrapper 把
encode、stream、collect 和 decode 这套重复流程放进一个函数：

```python
def generate_text_stream_concat(
        model, tokenizer, prompt, device, max_new_tokens,
        verbose=False,
):
    input_ids = torch.tensor(
        tokenizer.encode(prompt),
        device=device
    ).unsqueeze(0)

    generated_ids = []
    for token in generate_text_basic_stream_cache(
        model=model,
        token_ids=input_ids,
        max_new_tokens=max_new_tokens,
        eos_token_id=tokenizer.eos_token_id
    ):
        next_token_id = token.squeeze(0)
        generated_ids.append(next_token_id.item())

        if verbose:
            print(
                tokenizer.decode(next_token_id.tolist()),
                end="",
                flush=True
            )
    return tokenizer.decode(generated_ids)
```

- 函数显式接收 model、tokenizer、prompt、device 和 generation limit，方便在 benchmark loop 中
  重复调用。
- Encoding 和 `unsqueeze(0)` 准备一个 single-item batch。
- `generated_ids` 保存 Python integer；`.item()` 从单元素 tensor 中取出 scalar ID。
- `verbose=False` 让大规模评估保持安静。启用时，相同 ID 会被逐个解码和打印。
- Stream 结束后，最后一次 tokenizer 调用解码完整 ID list，并返回字符串。

## 4. 提取 final-answer candidate

Reasoning response 可能包含许多中间数字。Evaluator 首先查找最后一个 LaTeX `\boxed{...}`，同时还
要正确处理 nested braces：

```python
def get_last_boxed(text):
    boxed_start_idx = text.rfind(r"\boxed")
    if boxed_start_idx == -1:
        return None
    current_idx = boxed_start_idx + len(r"\boxed")

    while current_idx < len(text) and text[current_idx].isspace():
        current_idx += 1
    if current_idx >= len(text) or text[current_idx] != "{":
        return None
    current_idx += 1
    brace_depth = 1
    content_start_idx = current_idx

    while current_idx < len(text) and brace_depth > 0:
        char = text[current_idx]
        if char == "{":
            brace_depth +=1
        elif char == "}":
            brace_depth -= 1
        current_idx += 1
    if brace_depth != 0:
        return None
    return text[content_start_idx:current_idx-1]

import re
RE_NUMBER = re.compile(
    r"-?(?:\d+/\d+|\d+(?:\.\d+)?(?:[eE][+-]?\d+)?)"
)

def extract_final_candidate(text, fallback="number_then_full"):
    result = ""

    if text:
        boxed = get_last_boxed(text.strip())
    if boxed:
        result = boxed.strip().strip("$ ")
    elif fallback in ("number_then_full", "number_only"):
        m = RE_NUMBER.findall(text)
        if m:
            result = m[-1]
        elif fallback == "number_then_full":
            result = text
    return result
```

`get_last_boxed` 相当于一个小型 parser：

1. `rfind` 刻意选择最后一个 `\boxed`，因为 response 可能先讨论过其他 candidate。
2. Cursor 越过命令名，再跳过 whitespace。
3. 如果下一个非空白字符不是 `{`，说明结构不符合预期。
4. `brace_depth` 从 1 开始，遇到 nested `{` 时增加，遇到 `}` 时减少。
5. Depth 回到 0 时，就找到了与最初 opening brace 配对的 closing brace。
6. 如果到文本末尾 depth 仍不为 0，表达式不平衡，函数返回 `None`。

`RE_NUMBER` 为 signed fraction、decimal、integer 和 scientific notation 提供 fallback。
`extract_final_candidate` 优先返回 boxed answer，否则选择最后一个 numeric match；默认模式只有在没有
数字时才返回完整文本。

```python
print(extract_final_candidate(r"\boxed{ 14/3. }"))
```

结果是 `14/3.`。Extraction 暂时保留末尾句点，之后由 normalization 和 parser 判断 candidate 是否
有效。

## 5. 标准化数学写法

等价答案可能使用 LaTeX、Unicode、decimal 或 plain expression。Normalizer 的第一部分先定义替换
规则，并删除 special chat tokens：

```python
LATEX_FIXES = [
(r"\\left\s*", ""),
(r"\\right\s*", ""),
(r"\\,|\\!|\\;|\\:", ""),
(r"\\cdot", "*"),
(r"\u00B7|\u00D7", "*"),
(r"\\\^\\circ", ""),
(r"\\dfrac", r"\\frac"),
(r"\\tfrac", r"\\frac"),
(r"°", ""),
]

RE_SPECIAL = re.compile(r"<\|[^>]+?\|>")
SUPERSCRIPT_MAP = {
"⁰": "0", "¹": "1", "²": "2", "³": "3", "⁴": "4",
"⁵": "5", "⁶": "6", "⁷": "7", "⁸": "8", "⁹": "9",
"⁺": "+", "⁻": "-", "⁽": "(", "⁾": ")",
}

def normalize_text(text):
    if not text:
        return ""
    text = RE_SPECIAL.sub("", text).strip()

    match = re.match(r"^[A-Za-z]\s*[.:]\s*(.+)$", text)
    # Remove leading multiple choice labels and angle-degree makes
    if match:
        text = match.group(1)

    text = re.sub(r"\^\s*\{\s*\\circ\s*\}", "", text)
    text = re.sub(r"\^\s*\\circ", "", text)
    text = text.replace("°", "")

    # Unwrap "\text{...}" if the whole string is wrapped
    match = re.match(r"^\\text\{(?P<x>.+?)\}$", text)
    if match:
        text = match.group("x")
    # Strip LaTeX math display wrappers
    text = re.sub(r"\\\(|\\\)|\\\[|\\\]", "", text)

    for pat, rep in LATEX_FIXES:
        text = re.sub(pat, rep, text)

    def convert_superscripts(s, base=None):
        converted = "".join(
            SUPERSCRIPT_MAP[ch] if ch in SUPERSCRIPT_MAP else ch
            for ch in s
        )
        if base is None:
            return converted
        return f"{base}**{converted}"

    text = re.sub(r"([0-9A-Za-z\)\]\}])([⁰¹²³⁴⁵⁶⁷⁸⁹⁺⁻]+)",
                  lambda m: convert_superscripts(m.group(2), base=m.group(1)),
                  text,
                  )
    text = convert_superscripts(text)

    text = text.replace("\\%", "%").replace("$", "").replace("%", "")
    text = re.sub(
        r"\\sqrt\s*\{([^}]*)\}",
        lambda match: f"sqrt({match.group(1)})",
        text,
    )
    text = re.sub(
        r"\\sqrt\s+([^\\\s{}]+)",
        lambda match: f"sqrt({match.group(1)})",
        text,
    )
    text = re.sub(
        r"\\frac\s*\{([^{}]+)\}\s*\{([^{}]+)\}",
        lambda match: f"({match.group(1)})/({match.group(2)})",
        text,
    )
    text = re.sub(
        r"\\frac\s+([^\s{}]+)\s+([^\s{}]+)",
        lambda match: f"({match.group(1)})/({match.group(2)})",
        text,
    )
    text = text.replace("^", "**")
    text = re.sub(
        r"(?<=\d)\s+(\d+/\d+)",
        lambda match: "+" + match.group(1),
        text,
        )
    text = re.sub(
        r"(?<=\d),(?=\d\d\d(\D|$))",
        "",
        text,
    )
    return text.replace("{", "").replace("}", "").strip().lower()


```

Normalization 按明确的阶段进行：

- 空 input 变成空字符串，model-specific special token 被删除。
- `A:` 或 `b.` 这样的 multiple-choice label 被去掉。
- 几种 degree symbol 写法被删除，使角度答案可以按数值比较。
- 包住整个字符串的 `\text{...}` 与 LaTeX display delimiter 被拆开。
- `LATEX_FIXES` 删除 sizing、spacing command，统一 multiplication 写法，并把 `\dfrac`、`\tfrac`
  映射为 `\frac`。
- Unicode superscript 被转成普通字符；跟在 base 后的 superscript 变成 `2**2` 这样的 Python
  exponentiation。
- Square root 变成 `sqrt(...)`，fraction 变成带括号的 division，`^` 变成 `**`。
- 简单 fraction 前的 whitespace 可能表示 mixed number，因此被转换成 addition。
- `1,234` 中这样的 thousands separator 会被删除。
- 最后删除 brace、strip whitespace，并统一为 lowercase。

这是一套实用的转换规则，并不是完整 LaTeX grammar。Transformation 的顺序会影响结果，因此可接受
的 answer contract 应当保持足够窄，并由 test 固定下来。

## 6. 使用 SymPy 比较表达式

```python
from sympy.parsing import sympy_parser as spp
from sympy.core.sympify import SympifyError
from sympy.polys.polyerrors import PolynomialError
from tokenize import TokenError
from sympy import simplify

def sympy_parser(expr):
    if expr is None or len(expr) > 2000:
        return None
    try:
        return spp.parse_expr(
            expr,
            transformations=(
                *spp.standard_transformations,
                spp.implicit_multiplication_application,
            ),
            evaluate=True,
        )
    except (SympifyError, SyntaxError, TypeError, AttributeError,
            IndexError, TokenError, ValueError, PolynomialError):
         return None

def equality_check(expr_gtruth, expr_pred):
    if expr_gtruth == expr_pred:
        return True
    gtruth, pred = sympy_parser(expr_gtruth), sympy_parser(expr_pred)
    if gtruth is not None and pred is not None:
        try:
            return simplify(gtruth - pred) == 0
        except (SympifyError, TypeError):
            pass
    return False
```

- Wrapper 在 parsing 前拒绝 `None` 和异常长的 expression。
- `standard_transformations` 处理常规 SymPy syntax。
- `implicit_multiplication_application` 允许把 `2x` 理解为 `2*x`。
- 列出的 exception 会把 malformed answer 转成 `None`，而不是让整个 evaluation run 中止。
- `equality_check` 先做成本最低的 exact string equality。
- 如果两边都能 parse，就把它们相减并 simplify；差为零说明数学上等价。例如 `1/2` 和 `0.5`
  可以化简为零差值。
- Parsing 或 simplification 失败时返回 `False`。

`parse_expr` 不应被视为可安全执行任意恶意输入的 sandbox。Production evaluator 应隔离 parsing，
加入更严格的 allowlist 和 resource limit，或者采用刻意限制 grammar 的 parser。

## 7. 为单项和多项答案判分

```python
def split_into_parts(text):
    # split  expressions like "(a,b)" or "[a,b]" into ["a", "b"]
    result = [text]

    if text:
        if (
            len(text) >= 2
            and text[0] in "([" and text[-1] in ")]"
            and "," in text[1:-1]
        ):
             items = [p.strip() for p in text[1:-1].split(",")]
             # check if every entry is non-empty
             if all(items):
                result = items
    else:
        result = []
    return result

def grade_answer(pred_text, gt_text):
    result = False
    if pred_text is not None and gt_text is not None:
        gt_parts = split_into_parts(
            normalize_text(gt_text)
        )

        pred_parts = split_into_parts(
            normalize_text(pred_text)
        )

        if (gt_parts and pred_parts
            and len(gt_parts) == len(pred_parts)):
            result = all(
                equality_check(gt, pred)
                for gt, pred in zip(gt_parts, pred_parts)
            )
    return result



```

`split_into_parts` 只识别较窄的 tuple/list form：文本需要以括号或方括号开始和结束，并在内部包含
comma。只有所有 item 都非空时，拆分结果才替换原来的一项 list；空 input 得到空 parts。

`grade_answer` 分别标准化 ground truth 与 prediction，再把它们拆成 parts。只有 part 数量相同，并且
按顺序对应的每一项都等价时，答案才正确。因此 `(1, 2)` 与 `(2, 1)` 不相同。

### 把实现交给 coding agent，但保留清楚的 specification

Notebook 指出，只要明确描述 input、expected behavior、edge case 和安全要求，这类 parsing machinery
中的大量实现工作可以交给 coding agent：

```plain text
Implement a robust Python function:

    grade_answer(model_response: str, ground_truth: str) -> bool

It should grade answers produced by a math LLM. A model response may contain
prose, Markdown, LaTeX, special chat tokens, and a final answer such as:

    **Final Answer:** \boxed{\dfrac{14}{3}}

Extract the intended final answer, normalize common mathematical formats, and
determine whether it is mathematically equivalent to the ground truth. It
should handle common cases such as fractions, roots, exponents, decimals,
percentages, and tuple/list answers.

Use helper functions where they improve clarity. Handle malformed output
gracefully rather than raising exceptions. Add type hints, brief docstrings,
and representative tests.

Choose the implementation details and dependencies, but explain any important
limitations or security considerations.
```

Agent 可以自行选择 implementation detail，但 evaluator 的维护者仍需要审查 answer contract、数学
覆盖范围、failure behavior 和 parser security。

### 使用更清楚的 answer contract

大量 parsing complexity 来自允许模型输出任意 prose。如果 generator prompt 能强制 machine-readable
final-answer contract，提取过程会更可靠。Notebook 记录了下面的 specification：

```plain text
Our math-model prompt requires every response to end with exactly:

    <final_answer>ANSWER</final_answer>

Only the mathematical answer appears inside the tag. For example:

    <final_answer>\frac{14}{3}</final_answer>

Implement:

    grade_answer(model_response: str, ground_truth: str) -> bool

Extract the final tagged answer and compare it mathematically with the ground
truth. Treat equivalent forms such as \frac{2}{3}, 2/3, and 4/6 as equal.
Support common LaTeX fractions, roots, exponents, and multi-part answers.

If the required tag is absent or malformed, return False. Handle invalid input
without raising exceptions. Choose a clean implementation, use helper
functions where appropriate, and add representative tests.
```

这里的重点是：先定义输出格式，再扩展 heuristic parser。这样 evaluator 可以确定性地拒绝缺失或
malformed tag。

## 10. 渲染 prompt 并显示进度

```python
def render_prompt(prompt):
    template = (
        "You are a helpful math assistant.\n"
        "Answer the question and write the final result on a new line as:\n"
        "\\boxed{ANSWER}\n\n"
        f"Question:\n{prompt}\n\nAnswer:"
    )
    return template
import time

def eta_progress_message(
    processed,
    total,
    start_time,
    show_eta=False,
    label="Progress",
):
    progress = f"{label}: {processed}/{total}"
    pad_width = len(f"{label}: {total}/{total} | ETA: 00h 00m 00s")
    if not show_eta or processed <=0:
        return progress.ljust(pad_width)
    elapsed = time.time() - start_time
    if elapsed <= 0:
        return progress.ljust(pad_width)
    remaining = max(total - processed, 0)

    if processed:
        avg_time = elapsed / processed
        eta_seconds =  avg_time * remaining
    else:
        eta_seconds = 0
    eta_seconds = max(int(round(eta_seconds)), 0)
    minutes, rem_seconds = divmod(eta_seconds, 60)
    hours, minutes = divmod(minutes, 60)
    if hours:
        eta = f"{hours}h {minutes:02d}m {rem_seconds:02d}s"
    elif minutes:
        eta = f"{minutes:02d}m {rem_seconds:02d}s"
    else:
        eta = f"{rem_seconds:02d}s"

    message = f"{progress} | ETA: {eta}"
    return message.ljust(pad_width)

def evaluate_math_500_stream(
        model,
        tokenizer,
        device,
        math_data,
        out_path=None,
        max_new_tokens=512,
        verbose=False,
):
    if out_path is None:
        dev_name = str(device).replace(":", "-") # filename compatible with Windows
        out_path = Path(f"math500-{dev_name}.jsonl")

    num_examples = len(math_data)
    num_correct = 0
    start_time = time.time()

    with open(out_path, "w", encoding="utf-8") as f:
        for i, row in enumerate(math_data, start=1):
            # apply prompt template
            prompts = render_prompt(row["problem"])

            # generate response
            gen_text = generate_text_stream_concat(
                model, tokenizer, prompts, device,
                max_new_tokens=max_new_tokens,
                verbose=verbose,
            )

            # Extract and normalize the answer
            extracted = extract_final_candidate(
            gen_text
            )

            # Grade answer
            is_correct = grade_answer(
                extracted, row["answer"]
            )
            num_correct += int(is_correct)

            record = {
                "index": i,
                "problem": row["problem"],
                "gtruth_answer": row["answer"],
                "generated_text": gen_text,
                "extracted": extracted,
                "correct": bool(is_correct),
            }
            f.write(json.dumps(record, ensure_ascii=False) + "\n")

            progress_msg = eta_progress_message(
                processed=i,
                total=num_examples,
                start_time=start_time,
                show_eta=True,
                label="MATH-500",
            )
            print(progress_msg, end="\r", flush=True)

            if verbose:
                print(
                    f"\n\n{'='*50}\n{progress_msg}\n"
                    f"{'='*50}\nExtracted: {extracted}\n"
                    f"Expected:  {row['answer']}\n"
                    f"Correct so far: {num_correct}\n{'-'*50}"
                )
    seconds_elapsed = time.time() - start_time
    acc = num_correct / num_examples if num_examples else 0.0
    print(f"\nAccuracy: {acc*100:.1f}% ({num_correct}/{num_examples})")
    print(f"Total time: {seconds_elapsed/60:.1f} min")
    print(f"Logs written to: {out_path}")
    return num_correct, num_examples, acc




```

`render_prompt` 为模型提供 role、question，以及明确的 `\boxed{ANSWER}` 指令。这个 contract 正好与
extractor 的首选格式一致。

`eta_progress_message` 根据完成数量和 elapsed time 构造 display string：

- `pad_width` 为最长的预期 progress line 预留字符数。
- 尚未处理任何 item 或关闭 ETA 时，只返回经过 padding 的 progress。
- 每条已完成样本的平均秒数乘以剩余样本数，得到 estimated remaining time。
- 两次 `divmod` 把秒拆成 hour、minute 和 second。
- 函数选择最短的合适格式，再 padding，避免 terminal 上残留旧字符。

`evaluate_math_500_stream` 是完整 evaluation loop：

1. 如果 caller 没有给出路径，就建立 device-specific JSONL filename。替换 `:` 可让 `cuda:0` 这类
   名称兼容 Windows filename。
2. 初始化 example count、correct count，并开始计时。
3. 使用 `with` 打开 output file，即使评估失败也会正确关闭文件。
4. `enumerate(..., start=1)` 提供更适合人阅读的 one-based index。
5. 每道题依次经过 render、generate、extract 和 grade。
6. `int(is_correct)` 把 `True` 转成 1，把 `False` 转成 0，加入 running total。
7. 每行一个 JSON object，保存 problem、reference answer、完整 generation、extracted answer 和
   correctness；`ensure_ascii=False` 保留可读的 Unicode。
8. Carriage return 在 terminal 同一行更新进度；verbose mode 则打印每道题的详细 block。
9. 结束后，accuracy calculation 安全处理 empty dataset，时间转换为分钟，并返回三个 summary value。

## 12. 本章建立的基础

第 3 章把 evaluation 分成几个可以独立检查的层：

```text
generation correctness
  ≠ extraction correctness
  ≠ normalization correctness
  ≠ symbolic-comparison correctness
```

低分可能来自模型，也可能来自错误的 answer contract 或 grader。Unit-style examples 在 grader 被
用于 MATH-500 前先测试它；JSONL log 则保留足够信息，供之后审查每一项判断。因此这条 evaluation
pipeline 既是 benchmark runner，也是后续 reasoning-model training 的 debugging instrument。
