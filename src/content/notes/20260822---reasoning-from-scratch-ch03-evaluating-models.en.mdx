```python
from threading import local


def load_model_and_tokenizer(
        which_model, device, use_compile, local_dir="qwen3"
):
    if which_model == "base":
        download_qwen3_small(
            kind="base", tokenizer_only=False, out_dir=local_dir
        )

        tokenizer_path = Path(local_dir) / "tokenizer-base.json"
        model_path = Path(local_dir) / "qwen3-0.6B-base.pth"
        tokenizer = Qwen3Tokenizer(tokenizer_file_path=tokenizer_path)
    elif which_model == "reasoning":
        download_qwen3_small(
                    kind="reasoning", tokenizer_only=False, out_dir=local_dir
                )

        tokenizer_path = Path(local_dir) / "tokenizer-reasoning.json"
        model_path = Path(local_dir) / "qwen3-0.6B-reasoning.pth"
        tokenizer = Qwen3Tokenizer(
            tokenizer_file_path=tokenizer_path,
            apply_chat_template=True,
            add_generation_prompt=True,
            add_thinking=True,
            )
    else:
        raise ValueError(f"Invalid choice: which_model={which_model}")
    model = Qwen3Model(QWEN_CONFIG_06_B)
    model.load_state_dict(torch.load(model_path))

    model.to(device)

    if use_compile:
        torch._dynamo.config.allow_unspec_int_on_nn_module = True
        model = torch.compile(model)

    return model, tokenizer

```

The loader supports two model variants:

1. The `base` branch downloads base weights, points to the base tokenizer and checkpoint, and creates
   a tokenizer without a chat template.
2. The `reasoning` branch downloads the reasoning-tuned assets. Its tokenizer applies the chat
   template, adds the assistant-generation prompt, and enables thinking tokens.
3. Any other value raises `ValueError` immediately, rather than silently loading the wrong model.
4. After the branch chooses its paths, `Qwen3Model(QWEN_CONFIG_06_B)` constructs the common 0.6B
   architecture.
5. `torch.load` reads the checkpoint, and `load_state_dict` installs its weights.
6. `model.to(device)` keeps model parameters on the same device as later inputs.
7. When `use_compile` is true, the code enables Dynamo's unspecialized integer support and wraps the
   model with `torch.compile`.
8. The function returns the matched model-tokenizer pair.

## 2. Generating one mathematical answer

```python
from reasoning_from_scratch.ch02 import(
    generate_text_basic_stream_cache
)

prompt = (
    r"If $a+b=3$ and $ab=\tfrac{13}{6}$, "
    r"what is the value of $a^2+b^2$?"
)

input_token_ids_tensor = torch.tensor(
    tokenizer.encode(prompt),
    device=device
).unsqueeze(0) # add a batch dimension

all_token_ids = []

for token in generate_text_basic_stream_cache(
    model=model,
    token_ids=input_token_ids_tensor,
    max_new_tokens=2048,
    eos_token_id=tokenizer.eos_token_id
):
    token_id = token.squeeze(0) # remove the batch dimension
    decoded_id = tokenizer.decode(token_id.tolist())
    print(
        decoded_id,
        end="",
        flush=True
    )
    all_token_ids.append(token_id)

all_tokens = tokenizer.decode(all_token_ids)
```

The prompt asks for $a^2+b^2$ from $a+b=3$ and $ab=13/6$. The model can use
$(a+b)^2-2ab$ to obtain $14/3$.

The code proceeds in sequence:

- `generate_text_basic_stream_cache` reuses the KV-cached generator from Chapter 2.
- Raw strings preserve LaTeX backslashes such as `\tfrac`.
- `tokenizer.encode(prompt)` returns a one-dimensional Python list of token IDs.
- `torch.tensor(..., device=device)` creates the input on the same device as the model.
- `.unsqueeze(0)` adds a batch dimension, changing `(sequence_length,)` to
  `(1, sequence_length)`.
- Each streamed token includes that batch dimension. `squeeze(0)` removes it.
- `.tolist()` converts the token tensor into the form accepted by `tokenizer.decode`.
- `end=""` and `flush=True` display token fragments as a continuous live response.
- The token tensor is also saved in `all_token_ids` so the complete response can be reconstructed.

The model's response ends with `\boxed{\dfrac{14}{3}}`, which is mathematically correct.

### Encode/decode shape pattern

The notebook summarizes the boundary between Python lists and batched model tensors:

```python
ids = tokenizer.encode("Hello")                 # list[int], length L
x = torch.tensor(ids).unsqueeze(0)                # shape: (1, L)
```

`generate_text_basic_cache` returns the complete `(batch_size, generated_length)` tensor. Iterating
over that tensor iterates over its batch dimension, not over tokens. Token-by-token code should use
`generate_text_basic_stream_cache` instead.

## 3. Wrapping streamed generation

Benchmark evaluation should return one complete string while optionally preserving live output. The
wrapper encapsulates the repeated encode-stream-collect-decode pattern:

```python
def generate_text_stream_concat(
        model, tokenizer, prompt, device, max_new_tokens,
        verbose=False,
):
    input_ids = torch.tensor(
        tokenizer.encode(prompt),
        device=device
    ).unsqueeze(0)

    generated_ids = []
    for token in generate_text_basic_stream_cache(
        model=model,
        token_ids=input_ids,
        max_new_tokens=max_new_tokens,
        eos_token_id=tokenizer.eos_token_id
    ):
        next_token_id = token.squeeze(0)
        generated_ids.append(next_token_id.item())

        if verbose:
            print(
                tokenizer.decode(next_token_id.tolist()),
                end="",
                flush=True
            )
    return tokenizer.decode(generated_ids)
```

- The function accepts model, tokenizer, prompt, device, and generation limit explicitly, which
  makes it reusable inside the benchmark loop.
- Encoding and `unsqueeze(0)` prepare a single-item batch.
- `generated_ids` stores Python integers rather than tensors; `.item()` extracts the scalar ID.
- `verbose=False` keeps large evaluations quiet. When enabled, the same IDs are decoded and printed
  incrementally.
- Once the stream finishes, one tokenizer call decodes the complete list and returns a string.

## 4. Extracting a final-answer candidate

Reasoning responses may contain many intermediate numbers. The evaluator first looks for the last
LaTeX `\boxed{...}` expression and must handle nested braces correctly:

```python
def get_last_boxed(text):
    boxed_start_idx = text.rfind(r"\boxed")
    if boxed_start_idx == -1:
        return None
    current_idx = boxed_start_idx + len(r"\boxed")

    while current_idx < len(text) and text[current_idx].isspace():
        current_idx += 1
    if current_idx >= len(text) or text[current_idx] != "{":
        return None
    current_idx += 1
    brace_depth = 1
    content_start_idx = current_idx

    while current_idx < len(text) and brace_depth > 0:
        char = text[current_idx]
        if char == "{":
            brace_depth +=1
        elif char == "}":
            brace_depth -= 1
        current_idx += 1
    if brace_depth != 0:
        return None
    return text[content_start_idx:current_idx-1]

import re
RE_NUMBER = re.compile(
    r"-?(?:\d+/\d+|\d+(?:\.\d+)?(?:[eE][+-]?\d+)?)"
)

def extract_final_candidate(text, fallback="number_then_full"):
    result = ""

    if text:
        boxed = get_last_boxed(text.strip())
    if boxed:
        result = boxed.strip().strip("$ ")
    elif fallback in ("number_then_full", "number_only"):
        m = RE_NUMBER.findall(text)
        if m:
            result = m[-1]
        elif fallback == "number_then_full":
            result = text
    return result
```

`get_last_boxed` works as a small parser:

1. `rfind` deliberately selects the last `\boxed`, since a response may show earlier candidates.
2. The cursor advances past the command and skips whitespace.
3. If the next non-space character is not `{`, the structure is malformed.
4. `brace_depth` starts at one and increases for nested `{`, then decreases for `}`.
5. A depth of zero identifies the closing brace paired with the original opening brace.
6. Reaching the end with nonzero depth means the expression is unbalanced, so the function returns
   `None`.

`RE_NUMBER` provides a fallback for signed fractions, decimals, integers, and scientific notation.
`extract_final_candidate` prefers a boxed answer, otherwise selects the last numeric match. With the
default fallback, it returns the full text only when no numeric candidate exists.

```python
print(extract_final_candidate(r"\boxed{ 14/3. }"))
```

This prints `14/3.`. Extraction deliberately leaves the trailing period; later normalization and
parsing decide whether a candidate is valid.

## 5. Normalizing mathematical notation

Equivalent answers may be written as LaTeX, Unicode, decimals, or plain expressions. The first part
of the normalizer defines substitutions and removes special chat tokens:

```python
LATEX_FIXES = [
(r"\\left\s*", ""),
(r"\\right\s*", ""),
(r"\\,|\\!|\\;|\\:", ""),
(r"\\cdot", "*"),
(r"\u00B7|\u00D7", "*"),
(r"\\\^\\circ", ""),
(r"\\dfrac", r"\\frac"),
(r"\\tfrac", r"\\frac"),
(r"°", ""),
]

RE_SPECIAL = re.compile(r"<\|[^>]+?\|>")
SUPERSCRIPT_MAP = {
"⁰": "0", "¹": "1", "²": "2", "³": "3", "⁴": "4",
"⁵": "5", "⁶": "6", "⁷": "7", "⁸": "8", "⁹": "9",
"⁺": "+", "⁻": "-", "⁽": "(", "⁾": ")",
}

def normalize_text(text):
    if not text:
        return ""
    text = RE_SPECIAL.sub("", text).strip()

    match = re.match(r"^[A-Za-z]\s*[.:]\s*(.+)$", text)
    # Remove leading multiple choice labels and angle-degree makes
    if match:
        text = match.group(1)

    text = re.sub(r"\^\s*\{\s*\\circ\s*\}", "", text)
    text = re.sub(r"\^\s*\\circ", "", text)
    text = text.replace("°", "")

    # Unwrap "\text{...}" if the whole string is wrapped
    match = re.match(r"^\\text\{(?P<x>.+?)\}$", text)
    if match:
        text = match.group("x")
    # Strip LaTeX math display wrappers
    text = re.sub(r"\\\(|\\\)|\\\[|\\\]", "", text)

    for pat, rep in LATEX_FIXES:
        text = re.sub(pat, rep, text)

    def convert_superscripts(s, base=None):
        converted = "".join(
            SUPERSCRIPT_MAP[ch] if ch in SUPERSCRIPT_MAP else ch
            for ch in s
        )
        if base is None:
            return converted
        return f"{base}**{converted}"

    text = re.sub(r"([0-9A-Za-z\)\]\}])([⁰¹²³⁴⁵⁶⁷⁸⁹⁺⁻]+)",
                  lambda m: convert_superscripts(m.group(2), base=m.group(1)),
                  text,
                  )
    text = convert_superscripts(text)

    text = text.replace("\\%", "%").replace("$", "").replace("%", "")
    text = re.sub(
        r"\\sqrt\s*\{([^}]*)\}",
        lambda match: f"sqrt({match.group(1)})",
        text,
    )
    text = re.sub(
        r"\\sqrt\s+([^\\\s{}]+)",
        lambda match: f"sqrt({match.group(1)})",
        text,
    )
    text = re.sub(
        r"\\frac\s*\{([^{}]+)\}\s*\{([^{}]+)\}",
        lambda match: f"({match.group(1)})/({match.group(2)})",
        text,
    )
    text = re.sub(
        r"\\frac\s+([^\s{}]+)\s+([^\s{}]+)",
        lambda match: f"({match.group(1)})/({match.group(2)})",
        text,
    )
    text = text.replace("^", "**")
    text = re.sub(
        r"(?<=\d)\s+(\d+/\d+)",
        lambda match: "+" + match.group(1),
        text,
        )
    text = re.sub(
        r"(?<=\d),(?=\d\d\d(\D|$))",
        "",
        text,
    )
    return text.replace("{", "").replace("}", "").strip().lower()


```

The normalization stages are intentionally explicit:

- Empty input becomes an empty string, and model-specific special tokens are removed.
- A leading multiple-choice label such as `A:` or `b.` is stripped.
- Several degree-symbol forms are removed so angle answers can be compared numerically.
- A whole-string `\text{...}` wrapper and LaTeX display delimiters are unwrapped.
- `LATEX_FIXES` removes sizing and spacing commands, standardizes multiplication, and maps `\dfrac`
  and `\tfrac` to `\frac`.
- Unicode superscripts are converted to ordinary characters; superscripts attached to a base become
  Python-style exponentiation such as `2**2`.
- Square roots become `sqrt(...)`, fractions become parenthesized division, and `^` becomes `**`.
- Whitespace before a simple fraction can represent a mixed number, so it becomes addition.
- Thousands separators such as the comma in `1,234` are removed.
- Braces are removed, surrounding whitespace is stripped, and case is normalized.

This is a practical parser, not a complete LaTeX grammar. The order of transformations matters, and
the supported answer contract should stay narrow enough to test.

## 6. Comparing expressions with SymPy

```python
from sympy.parsing import sympy_parser as spp
from sympy.core.sympify import SympifyError
from sympy.polys.polyerrors import PolynomialError
from tokenize import TokenError
from sympy import simplify

def sympy_parser(expr):
    if expr is None or len(expr) > 2000:
        return None
    try:
        return spp.parse_expr(
            expr,
            transformations=(
                *spp.standard_transformations,
                spp.implicit_multiplication_application,
            ),
            evaluate=True,
        )
    except (SympifyError, SyntaxError, TypeError, AttributeError,
            IndexError, TokenError, ValueError, PolynomialError):
         return None

def equality_check(expr_gtruth, expr_pred):
    if expr_gtruth == expr_pred:
        return True
    gtruth, pred = sympy_parser(expr_gtruth), sympy_parser(expr_pred)
    if gtruth is not None and pred is not None:
        try:
            return simplify(gtruth - pred) == 0
        except (SympifyError, TypeError):
            pass
    return False
```

- The wrapper rejects `None` and unusually long expressions before parsing.
- `standard_transformations` handle normal SymPy syntax.
- `implicit_multiplication_application` allows forms such as `2x` to be interpreted as `2*x`.
- The listed exceptions turn malformed answers into `None` instead of stopping the evaluation run.
- `equality_check` first uses cheap exact string equality.
- If both strings parse, subtracting them and simplifying tests mathematical equivalence. For
  example, `1/2` and `0.5` simplify to a zero difference.
- Failed parsing or simplification returns `False`.

`parse_expr` should not be treated as a safe sandbox for arbitrary hostile input. A production
evaluator should isolate parsing, apply stricter allowlists and resource limits, or use a parser with
a deliberately restricted grammar.

## 7. Grading single and multi-part answers

```python
def split_into_parts(text):
    # split  expressions like "(a,b)" or "[a,b]" into ["a", "b"]
    result = [text]

    if text:
        if (
            len(text) >= 2
            and text[0] in "([" and text[-1] in ")]"
            and "," in text[1:-1]
        ):
             items = [p.strip() for p in text[1:-1].split(",")]
             # check if every entry is non-empty
             if all(items):
                result = items
    else:
        result = []
    return result

def grade_answer(pred_text, gt_text):
    result = False
    if pred_text is not None and gt_text is not None:
        gt_parts = split_into_parts(
            normalize_text(gt_text)
        )

        pred_parts = split_into_parts(
            normalize_text(pred_text)
        )

        if (gt_parts and pred_parts
            and len(gt_parts) == len(pred_parts)):
            result = all(
                equality_check(gt, pred)
                for gt, pred in zip(gt_parts, pred_parts)
            )
    return result



```

`split_into_parts` recognizes a narrow tuple/list form only when the text begins and ends with
matching-style delimiters and contains a comma. Nonempty items replace the original one-part list;
empty input becomes no parts.

`grade_answer` normalizes ground truth and prediction independently, splits each into parts, requires
the same number of parts, and checks corresponding expressions in order. Consequently `(1, 2)` and
`(2, 1)` are different answers.

### Delegating the implementation without losing the specification

The notebook notes that a coding agent can implement much of this parsing machinery when the task
describes inputs, expected behavior, edge cases, and safety requirements clearly:

```plain text

    **Final Answer:** \boxed{\dfrac{14}{3}}

should handle common cases such as fractions, roots, exponents, decimals,
percentages, and tuple/list answers.

Use helper functions where they improve clarity. Handle malformed output
gracefully rather than raising exceptions. Add type hints, brief docstrings,

```

The agent can choose implementation details, but the evaluator's owner still needs to review its
answer contract, mathematical coverage, failure behavior, and parser security.

### A clearer answer contract

Much of this parsing complexity comes from accepting unrestricted prose. If the generator prompt can
enforce a machine-readable final-answer contract, extraction becomes more reliable. The notebook
records this possible specification:

```plain text
Our math-model prompt requires every response to end with exactly:

    <final_answer>ANSWER</final_answer>

Only the mathematical answer appears inside the tag. For example:

    <final_answer>\frac{14}{3}</final_answer>

Implement:

    grade_answer(model_response: str, ground_truth: str) -> bool

Extract the final tagged answer and compare it mathematically with the ground
truth. Treat equivalent forms such as \frac{2}{3}, 2/3, and 4/6 as equal.
Support common LaTeX fractions, roots, exponents, and multi-part answers.

If the required tag is absent or malformed, return False. Handle invalid input
without raising exceptions. Choose a clean implementation, use helper
functions where appropriate, and add representative tests.
```

The important design lesson is to specify the output format before expanding a heuristic parser.
The evaluator can then reject missing or malformed tags deterministically.

## 10. Rendering prompts and reporting progress

```python
def render_prompt(prompt):
    template = (
        "You are a helpful math assistant.\n"
        "Answer the question and write the final result on a new line as:\n"
        "\\boxed{ANSWER}\n\n"
        f"Question:\n{prompt}\n\nAnswer:"
    )
    return template
import time

def eta_progress_message(
    processed,
    total,
    start_time,
    show_eta=False,
    label="Progress",
):
    progress = f"{label}: {processed}/{total}"
    pad_width = len(f"{label}: {total}/{total} | ETA: 00h 00m 00s")
    if not show_eta or processed <=0:
        return progress.ljust(pad_width)
    elapsed = time.time() - start_time
    if elapsed <= 0:
        return progress.ljust(pad_width)
    remaining = max(total - processed, 0)

    if processed:
        avg_time = elapsed / processed
        eta_seconds =  avg_time * remaining
    else:
        eta_seconds = 0
    eta_seconds = max(int(round(eta_seconds)), 0)
    minutes, rem_seconds = divmod(eta_seconds, 60)
    hours, minutes = divmod(minutes, 60)
    if hours:
        eta = f"{hours}h {minutes:02d}m {rem_seconds:02d}s"
    elif minutes:
        eta = f"{minutes:02d}m {rem_seconds:02d}s"
    else:
        eta = f"{rem_seconds:02d}s"

    message = f"{progress} | ETA: {eta}"
    return message.ljust(pad_width)

def evaluate_math_500_stream(
        model,
        tokenizer,
        device,
        math_data,
        out_path=None,
        max_new_tokens=512,
        verbose=False,
):
    if out_path is None:
        dev_name = str(device).replace(":", "-") # filename compatible with Windows
        out_path = Path(f"math500-{dev_name}.jsonl")

    num_examples = len(math_data)
    num_correct = 0
    start_time = time.time()

    with open(out_path, "w", encoding="utf-8") as f:
        for i, row in enumerate(math_data, start=1):
            # apply prompt template
            prompts = render_prompt(row["problem"])

            # generate response
            gen_text = generate_text_stream_concat(
                model, tokenizer, prompts, device,
                max_new_tokens=max_new_tokens,
                verbose=verbose,
            )

            # Extract and normalize the answer
            extracted = extract_final_candidate(
            gen_text
            )

            # Grade answer
            is_correct = grade_answer(
                extracted, row["answer"]
            )
            num_correct += int(is_correct)

            record = {
                "index": i,
                "problem": row["problem"],
                "gtruth_answer": row["answer"],
                "generated_text": gen_text,
                "extracted": extracted,
                "correct": bool(is_correct),
            }
            f.write(json.dumps(record, ensure_ascii=False) + "\n")

            progress_msg = eta_progress_message(
                processed=i,
                total=num_examples,
                start_time=start_time,
                show_eta=True,
                label="MATH-500",
            )
            print(progress_msg, end="\r", flush=True)

            if verbose:
                print(
                    f"\n\n{'='*50}\n{progress_msg}\n"
                    f"{'='*50}\nExtracted: {extracted}\n"
                    f"Expected:  {row['answer']}\n"
                    f"Correct so far: {num_correct}\n{'-'*50}"
                )
    seconds_elapsed = time.time() - start_time
    acc = num_correct / num_examples if num_examples else 0.0
    print(f"\nAccuracy: {acc*100:.1f}% ({num_correct}/{num_examples})")
    print(f"Total time: {seconds_elapsed/60:.1f} min")
    print(f"Logs written to: {out_path}")
    return num_correct, num_examples, acc




```

`render_prompt` gives the model a role, a question, and an explicit `\boxed{ANSWER}` instruction.
That contract matches the extractor's preferred format.

`eta_progress_message` computes a display string from completed items and elapsed time:

- `pad_width` reserves enough characters for the longest expected progress line.
- Before any item is processed, or when ETA display is disabled, the function returns only padded
  progress.
- Average seconds per completed example multiplied by remaining examples estimates time remaining.
- Two `divmod` calls break seconds into hours, minutes, and seconds.
- The shortest appropriate time format is selected, then padded to avoid leftover terminal text.

`evaluate_math_500_stream` is the complete evaluation loop:

1. It creates a device-specific JSONL filename unless the caller provides one. Replacing `:` keeps
   names such as `cuda:0` compatible with Windows filenames.
2. It initializes example and correct-answer counts and starts the timer.
3. Opening the output file with `with` ensures it closes even if evaluation fails.
4. `enumerate(..., start=1)` provides human-readable one-based indices.
5. Every problem is rendered, generated, extracted, and graded using the earlier helpers.
6. `int(is_correct)` turns `True` into one and `False` into zero for the running total.
7. One JSON object per line stores the problem, reference answer, full generation, extracted answer,
   and correctness. `ensure_ascii=False` preserves readable Unicode.
8. A carriage return updates progress on the same terminal line; verbose mode prints a detailed
   per-example block instead.
9. At the end, accuracy safely handles an empty dataset, timing is converted to minutes, and the
   three summary values are returned.

## 12. What this chapter establishes

Chapter 3 separates evaluation into small, inspectable layers:

```text
generation correctness
  ≠ extraction correctness
  ≠ normalization correctness
  ≠ symbolic-comparison correctness
```

A low score can come from the model, but it can also come from a broken answer contract or grader.
The unit-style examples test the grader before it is trusted on MATH-500, while the JSONL log keeps
enough evidence to audit individual decisions afterward. This evaluation pipeline is therefore both
a benchmark runner and a debugging instrument for later reasoning-model training.
